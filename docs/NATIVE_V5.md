# Lite2API Native v5

日期：2026-08-18

## 目标

Native v5 不再把 Lite2API 当作通用 SaaS Dashboard。它是一个单管理员、低频配置、高频判断的本地控制工具。

视觉和结构目标只有四条：

1. 一眼知道当前是否可用。
2. 一次只操作一个对象。
3. 内容本身形成层级，不用卡片墙制造层级。
4. 高级配置只在需要时出现。

## 核心结构

### 总览

`状态 → 四个核心数字 → 路由 / 异常 → 最近请求 → 可选趋势`

健康结论和四项指标属于同一个状态摘要，不是五张独立卡片。趋势图默认降级为可展开证据。

### 路由

使用真正的 master-detail：

`左侧模型列表 → 右侧当前路由详情`

页面不会同时纵向展开 Claude、Gemini、Codex 等全部路由。左侧负责“选谁”，右侧负责“改什么”。

### 上游

页面只有两个语义视图：

- 账号：身份、真实额度、冷却、可用性。
- 连接：真正参与路由的 API / 适配器连接。

原有汇总 KPI 仍保留给业务渲染，但在主界面隐藏，因为“账号数量”不是首要判断。

### 客户端

默认主体是 API Key 列表。创建 Key 使用按需弹窗；安全预设、高级限制不会永久占据首屏。新密钥创建成功后才展示一次性明文与客户端配置。

## 构建方式

`index.html` 继续保留稳定的业务函数、OAuth/导入导出/诊断等低频能力。Go 嵌入层在编译时替换：

- 应用 Shell
- 总览 markup
- 路由 markup
- 上游 markup
- 客户端 markup
- 全部视觉 CSS

最终浏览器收到的 HTML 已经是 Native v5 DOM，不再加载 Quiet Control 或 Apple v4 后再搬运旧 Dashboard 节点。

主要源文件：

- `native-v5-shell.html`
- `native-v5-monitor.html`
- `native-v5-routes.html`
- `native-v5-accounts.html`
- `native-v5-keys.html`
- `native-v5.css`
- `native-v5.js`

## 视觉规则

- 系统字体。
- 浅色：`#f5f5f7` 画布、白色内容面、`#1d1d1f` 正文、系统蓝交互。
- 深色：Apple 系统灰层级，不使用深蓝科技背景。
- 蓝色只表示交互和选择。
- 绿色只表示已验证健康。
- 页面层级优先使用留白、字号、对齐、分割线。
- 一个 master-detail 容器可以存在；同层级不允许重新退化为大量独立卡片。
- 删除装饰性渐变、发光、hover lift、永久教程条、永久创建面板。

## 审查标准

把页面截图缩小到 25% 时，仍应一眼看到：

- 左侧应用导航；
- 当前页面标题；
- 一个明确的内容主轴；
- 路由页的左列表 / 右详情；
- 上游页的账号 / 连接分段；
- 客户端页的 Key 列表。

如果缩小后只剩大量同权重矩形框，即视为回归失败。
