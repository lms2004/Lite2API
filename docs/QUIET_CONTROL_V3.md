# Lite2API Quiet Control v3

日期：2026-08-17  
范围：`internal/web` 管理台视觉系统、核心页面层级、响应式行为、键盘效率与构建验证。

## 1. 目标

Quiet Control 将 Lite2API 管理台定义为单管理员的运行控制面，而不是通用 SaaS 后台。

页面首先帮助操作者回答三个问题：

1. 网关现在能否正常提供流量？
2. 当前结论由什么运行证据形成？
3. 下一步最相关的操作是什么？

信息优先级固定为：

`系统健康 → 异常与容量 → 路由 → 请求证据 → 上游与客户端 → 低频诊断能力`

## 2. 设计语义

- 蓝色：交互、选择、焦点和主操作。
- 绿色：经过真实运行证据验证的健康或成功。
- 黄色：仍可工作，但需要关注。
- 红色：失败、不可用或危险操作。
- 灰色：未知、未观测、停用或次要信息。

未知状态不得渲染为 0。装饰性渐变、发光、悬浮卡片和无意义胶囊不属于默认视觉语言。

核心尺寸：

- 控件圆角：7 px。
- 面板圆角：9 px。
- 浮层圆角：13 px。
- 默认表格行高：40 px。
- 舒适密度行高：46 px。
- 桌面侧栏：204 px。

## 3. 架构

现有 `index.html` 继续负责稳定的 DOM、API 调用、状态管理和业务逻辑。为了避免在 22 万字节单文件中继续叠加历史 CSS，Quiet Control 使用 Go 嵌入层进行构建时组装：

1. 嵌入原始 `index.html`。
2. 找到唯一的 `<style>` 区域。
3. 用三份规范化 CSS 替换历史样式内容。
4. 在 `</body>` 前注入非侵入式增强脚本。
5. 继续向服务器暴露单一的 `IndexHTML` 字节数组。

源文件：

- `quiet-control-core.css`：令牌、基础控件、应用壳层和通用组件。
- `quiet-control-pages.css`：总览、路由、上游、客户端和诊断页面。
- `quiet-control-enhancements.css`：命令面板、详情侧栏、草稿栏和响应式规则。
- `quiet-control.js`：键盘、渐进披露、移动语义和焦点增强。

这种方式不改变管理 API，也不要求引入 React、Node 构建链或额外运行时依赖。

## 4. 页面变化

### 4.1 运行总览

- 健康结论保持在第一阅读层。
- 四个指标合并为连续运行摘要带，减少独立卡片竞争。
- 路由健康和最近异常保持在请求证据之前。
- 两张趋势图进入可折叠区域，低流量时不持续占据首屏。
- 请求表行可通过键盘打开右侧详情。

### 4.2 模型路由

- 模型意图和真实渠道链使用更紧凑的单一结构。
- 首次说明可隐藏，并记住操作者选择。
- 存在未保存修改时显示固定草稿栏。
- 草稿栏提供查看差异、放弃修改和保存热加载三个动作。
- `Cmd/Ctrl + Enter` 可保存路由修改。

### 4.3 上游来源

上游页面新增两个内部视图：

- 账号与额度：认证身份、套餐、额度、重置与冷却。
- API 与连接：Base URL、协议、模型覆盖、并发和运行状态。

现有节点被移动到对应视图中，不复制数据，也不改变后端实体。

### 4.4 客户端访问

- 安全预设仍是创建 Key 的主入口。
- 客户端配置中心只在当前浏览器持有本次新建明文 Key 时显示。
- Key 表格继续是长期管理主体。
- 连接验证继续使用只读模型端点，不产生模型调用费用。

## 5. 全局交互

### 命令面板

`Cmd/Ctrl + K` 打开全局命令面板，支持：

- 页面跳转。
- 接入上游。
- 创建 Key。
- 搜索或筛选失败请求。
- 保存路由修改。
- 刷新状态。
- 切换密度。
- 打开诊断能力。

### 键盘与焦点

- `/` 聚焦当前页面搜索框。
- `Esc` 关闭右侧详情。
- 表格行支持 `Enter` 和空格打开详情。
- 弹窗打开后聚焦首个可用控件。
- 弹窗和详情关闭后将焦点归还给触发元素。
- 路由原有 `Alt + ↑/↓` 排序能力保持不变。

### 密度

工具栏可以在紧凑和舒适密度之间切换，选择保存到本地浏览器，不改变服务端配置。

## 6. 响应式

- `>1180 px`：完整侧栏和宽数据表。
- `701–1180 px`：72 px 图标侧栏，次级结构自动收敛。
- `≤700 px`：仅保留总览、路由、上游、客户端四个底部导航项。
- 移动表格标签由 JavaScript 根据真实表头写入 `data-label`，不再依赖脆弱的 `nth-child()` 列序号。
- 详情在窄屏变为全宽侧栏。
- 支持 `prefers-reduced-motion` 和 `prefers-contrast: more`。

## 7. 质量门禁

`quiet_control_test.go` 验证：

- 构建结果包含 Quiet Control 令牌和行为层。
- 历史视觉补丁不会泄漏到最终页面。
- 最终页面仍只有一个 `<style>`。
- HTML 结束结构保持完整。
- 构建器能正确替换 CSS、注入 JavaScript，并在锚点缺失时安全降级。

GitHub Actions 工作流 `.github/workflows/ui-quality.yml` 执行：

- `gofmt` 检查。
- `go test ./...`。
- Quiet Control 源文件与关键设计契约检查。
- `node --check internal/web/quiet-control.js`。

## 8. 不变的产品边界

本轮不修改：

- 管理 API 路径和请求结构。
- OAuth、导入导出、Key、路由和监控的数据模型。
- VPN、会话、CSRF 或上游凭据安全边界。
- 单 Go 二进制和无前端构建工具链的部署方式。

因此，本轮属于管理台视觉与交互系统重构，不是网关运行逻辑重写。

## 9. 后续验收

合并前应至少检查：

- 1440、1024、768、390 和 320 px。
- healthy、degraded、unavailable、stale 和 empty 状态。
- OAuth、创建 Key、路由保存、导入和删除确认。
- 长账号名、长错误、无 usage、无额度观测和大量请求记录。
- 全键盘操作和 reduced motion。
