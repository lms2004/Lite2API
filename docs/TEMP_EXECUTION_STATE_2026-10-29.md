## 对齐基准

本轮以以下资料为目标和验收边界：

- `docs/BUSINESS_CAPABILITIES.md`：Mermaid 表达能力归属、职责边界和验收原则。容器与虚线表示归属和支撑，不强行解释成程序调用顺序。
- `docs/BUSINESS_USE_CASES.md`：八个用例，覆盖来源、工具、调用、使用控制、换渠道、恢复调用、升级和恢复服务。
- `AGENTS.md`：程序负责认证、授权、限额、能力过滤、有限恢复、完整交付和观测；Agent 只能执行证据收集、实际验收和维护工作，不能用生成配置或“进程启动”代替程序能力。

核心验收语义如下：

1. 目录、登录、HTTP 200、EOF、进程存活和 OAuth 刷新成功都不能单独证明真实调用完成。
2. `declared`、`verified`、`unsupported`、`unknown` 必须保持不同含义；未知允许尝试，明确不支持必须排除，包括备用目标。
3. 能力事实必须绑定来源、上游模型、接口、特性、推理强度、实际凭据和观测时间；来源或映射变化后旧事实失效。
4. 工具验收必须是真实的两跳往返；图片验收必须发送原生多模态内容；流式验收必须检查协议终止事件和终止后的尾帧。
5. 一次逻辑调用内部可以有限换源，但提交结果不确定时不自动重放；流已经开始后不跨来源拼接。
6. 客户端权限、模型范围、RPM、并发、过期和撤销必须影响后续真实请求；管理凭据与客户端凭据必须分离。
7. 升级、备份和恢复只有在受影响的真实调用完成后才算恢复成功；夹具通过不等于真实灾备通过。

## 已执行的改造

### 1. 能力证据和来源验收

- 新增能力事实模型、特性键、来源身份摘要、范围校验、克隆和生命周期处理。
- `/admin/api/accounts/verify` 支持 `call`、`stream`、`tools` 和 `image_input`，结果同时返回 `ok`、`completed`、`evidence_saved`，避免把 HTTP 状态当成验收结果。
- 图片验收使用内置 1x1 PNG，并按 Responses、Chat、Anthropic Messages 分别生成原生图片请求。
- 工具验收要求实际工具调用、结果回传、第二跳使用原凭据，并检查最终结果包含工具结果。
- 失败不会把能力推断为“不支持”；显式 `unsupported` 在失败检查后继续保留。
- 能力目录、模型映射和运行时选择逻辑已经处理重复逻辑模型、显式负面事实、裸 `model_map` 别名和不可用备用来源。
- 能力证据的 `upstream_model` 绑定已加入校验；来源或模型变化时会把旧事实降为 `unknown` 并修正当前作用域。

### 2. 请求要求和完整交付

- 在选择来源前拒绝跨接口字段：Responses 专属字段不能进入 Chat/Messages；工具、流式、推理字段不能进入 Embeddings、Images、Rerank 等不支持的接口。
- 普通响应和流式响应均检查协议完成条件、选择数、终止事件、工具结构、错误事件和尾帧；`[DONE]`、`response.completed`、`message_stop` 后再出现内容会失败。
- 不再把诊断探针的多 choice 响应当成单 choice 完成。
- 保留取消、容量、失败重试边界和不确定提交保护。

### 3. 路由、模型和运行观测

- 调度器支持逻辑模型和 `model_map` 别名，显式 `unsupported` 的上游不会进入模型目录或备用候选。
- 路由健康按账号、凭据、上游模型和推理强度建立目标作用域，不再把同一连接上的不同目标合并成一个健康结论。
- 重复的账号、凭据、模型、推理组合在服务端和管理台均会被拒绝。
- 观测区分新鲜调用、历史记录、未知、降级和不可用；请求记录保留接口、流模式、目标模型、凭据范围和完成契约摘要。

### 4. OAuth、适配器和导入

- OAuth 管理调用检查 HTTP 200 中的业务失败状态，不再把 `{status:"error"}` 当成成功。
- OAuth 状态大小写归一化；池账号的 Base URL 从实际管理适配器地址派生，不再硬编码默认端口。
- 适配器目录探针跟随 `CLIPROXYAPI_MANAGEMENT_URL`，使管理台探针、池账号和实际调用使用同一地址。
- OAuth 导入在凭据上传成功但共享池停用或不可用时，不再把导入标成整体 `Applied`。
- 维护补丁、Compose、Dockerfile、systemd 安装器的 CLIProxyAPI 版本、提交和日期已同步为同一发布元数据。

### 5. 权限和维护边界

- 托管客户端 Key 的模型权限、RPM、并发、过期和撤销路径已有真实请求测试。
- 新增托管 Key 与管理员 Token 的哈希冲突检查，覆盖初次加载和热加载。
- 配置事务继续使用版本检查、影响范围和原子写入；账号导入也接受预期配置版本。
- 安装器在读取既有 Lite2API 配置前先检查符号链接和目录安全边界。
- `Makefile run` 不再引用仓库中不存在的 `data/config.json`，默认使用 `config.example.json`，可通过 `CONFIG=...` 指定真实配置。

### 6. 管理台、Agent 指导和文档

- 管理台增加图片输入验收选项，模型映射、重复目标和能力负面事实的可见性与运行时保持一致。
- 连接测试明确显示“目录声明”不等于真实调用和特性验收；三轮探针说明是调用完整性观测，不评价模型回答质量。

- `tools/verify-business-runtime.py` 复用部署验收的严格协议判定，校验 `--only` 白名单，覆盖 wildcard/all-accounts 来源选择，并在必需用例失败时返回非零。

6. 管理台普通探针需要和能力验证一样限制在已声明模型或明确通配范围内，不能仅因账号启用就对任意输入模型发起上游请求。

8. OAuth 导入在外部上传凭据后遇到配置版本冲突时仍有孤儿凭据风险，需要把上传和配置变更放入可补偿的边界，或在冲突时删除已上传文件；OAuth-only 导入同样需要重新检查版本。
