# Lite2API 业务对齐与验收记录

> 本文保留第一轮对应源码的历史结果。工具往返、精确来源事实、受控变更、发布门禁及真实加密恢复的后续改造与新证据见[第二轮记录](BUSINESS_ALIGNMENT_ROUND2_2026-10-28.md)；下文“未覆盖”只描述第一轮范围。

依据：[用户提供的完整目标稿与 Mermaid](BUSINESS_CAPABILITIES.md)。交付范围为 `/root/Lite2API` 仓库，保留开始时已有的四组未跟踪说明/证据；不更改目标，不替换生产网关或适配器。本文区分源码、隔离 HTTP 验证和实际客户端/上游验收。

## 改造结果与依据

| 实质偏差 | 最终行为 | 可复核依据 |
| --- | --- | --- |
| HTTP 200、EOF 被当成成功 | 按实际接口检查 JSON 结构与完成字段；SSE 检查正确终态；200 error、截断和模式不匹配均失败 | `response_completion.go`、`response_completion_test.go`、`response_delta_compat_test.go` |
| 大响应无法在提交后返回 502 | 小 JSON 最多预留 64 KiB 校验；大 JSON 增量扫描，未完成时中止 HTTP 连接；已开始 SSE 发送脱敏 error，均不重放 | `gateway.go:streamResponse`；大 JSON 真实 HTTP/声明长度/压缩测试 |
| 自制检查可能误认完成 | 隔离协议字段、结构路径、重复关键字段及必需产物；修复独立审查复现的 13 个误判场景 | `completion_review_test.go`，修复前复现、修复后通过 |
| 实际 Responses SSE 被误拒绝 | Responses 的文本、推理、工具参数字符串 delta 与 Anthropic 对象 delta 分开解析，保留终态要求 | 实际失败记录、源码根因、专项测试及真实流复验 |
| 选择来源时没有请求特性约束 | 先满足模型、接口、图片/工具/流式与推理约定，再比较偏好；明确不支持的备用同样排除 | `request_requirements.go`、`runtime.go` 及 HTTP fallback 测试 |
| 目录发现等同于能力事实 | 分开声明/验证/不支持/未知；目录只生成 `declared`，保留已有验证和负面事实 | `capability_evidence.go`、`capabilitysync.go` 及配置/发现回归 |
| 推理参数静默覆盖或删除 | 冲突返回 400；Responses 写入原生 `reasoning.effort`；Messages 拒绝 OpenAI 强度，保留原生 `thinking` | `request_rewrite_operation.go`、`claude_compat_test.go` |
| 增量续接会换源或被适配器删字段 | 非空 `previous_response_id` 仅允许唯一、固定模型的原生直接来源；多源/CLIProxy/其他适配器返回 400，要求完整历史 | `continuation.go`、`continuation_test.go`；CLIProxy HTTP 源码删除字段的证据见 routing 审查记录 |
| 可用性故障被压成一个标签 | 区分无合格来源、已知不可用、满载和排队超时；保留逻辑调用失败，计入总样本 | `gateway.go`、`TestGatewayExplainsUnavailableSourcesAndCapacity` |
| 目录轮询的时间戳引发无意义重载 | 同一声明版本保留观测时间；纯证据来源/时间不改变路由身份，能力状态/模型/特性改变仍使旧证据失效 | `capability_evidence_lifecycle_test.go`：成功调用后重复发现不变更 runtime、磁盘配置及成功观测 |
| 一次调用内发送事实不可追踪 | 一个逻辑结果关联有界 `attempts`；含 OAuth 刷新后重试；仅受信适配器的公开索引可充当实际凭据身份 | `stats.go`、`oauthrecovery.go`、OAuth 两次发送/一次逻辑调用测试 |
| 不同接口/账号观测互相覆盖；旧成功当当前健康 | 按别名、目标、接口和流模式保留事实；历史继续可见，5 分钟后不作为近期可用证据；配置及完成契约版本隔离旧证据 | `operations.go`、`server.go`、`requestlog.go`；跨接口失败、重启、重载与历史新鲜度测试 |
| 前端仍把 200 断流显示为成功 | 统一按 `outcome` 统计、显示调用结果与发送轨迹；目录检查不再叫“已验证模型” | `app-metrics.js`、`app-shared.js`、`app-usage.js` 及 Node 业务回归 |
| epoch 前的过期 Key 被视为无限期 | 明确的过期时间始终按实际时间比较；撤销与改权限影响后续请求，更新/重载保留既有租约与 RPM 状态 | `clientkeys*.go`、`clientkeys_access_test.go` |
| 管理 URL/连接探测/导入可泄露或保存展示掩码 | URL 查询与代理身份脱敏；原样掩码回填、修改要求完整值；导入共用规则；诊断不跟随重定向，不回传原始网络/授权错误 | `information.go`、`accounttest.go`、`admin.go`、`accountimport.go`、`prompttest.go` 及安全业务测试 |

完成检查使用有界内存：JSON 深度最多 128，短标记最多 512 字节，SSE 单行/事件最多 1 MiB、choice 索引最多 128 个。超出范围明确失败。逻辑调用最多保留前 64 次发送明细，并另存总发送次数和最终结果；健康索引最多保留 16384 个组合，不复制发送明细。没有引入数据库、注册中心、独立监控服务或额外后台探测。

## 全部能力的归属与验收范围

| 能力 | 程序主责及保留实现 | 本轮证据与边界 |
| --- | --- | --- |
| 接入账号 | 管理路由连接，OAuth 适配器管理真实凭据与池；保留账号/连接/公开凭据索引关系 | 导入、更新、删除、导出回归；真实调用识别所选连接，不以连接数当真实账号数 |
| 维护授权 | 受信 401 最多一次刷新、并发合并及失败退避；永久 grant 失效交用户重登 | OAuth 隔离请求验证；未主动刷新或重新登录生产账号，既有恢复记录不冒充本轮证明 |
| 确认能力 | 有范围、依据和时间的能力事实；未知允许尝试，负面事实排除 | 配置/发现/特性筛选实测；未把目录或整个池标成已验证 |
| 提供入口 | 固定路径、协议认证、模型目录和客户端配置 | curl 六种接口/流模式，以及真实 Claude Code、Codex CLI；不是仅生成配置 |
| 管理模型名 | 稳定别名、显式映射与作者允许的目标集合 | 模型/推理冲突和备用筛选回归；不同模型替代仍由显式路由定义授权 |
| 保持兼容 | 按操作透传必要参数，协议错误与完成条件分开 | Chat、Responses、Messages 首批真实范围通过；Embedding/Images/Rerank 仅隔离完成检查，不声明真实供应商验收 |
| 判断可用 | 请求要求、授权/故障/冷却与容量分别处理 | 无候选/不可用/满载/超时分支实测；目录、历史成功与未知额度均不能替代当前可用证明 |
| 选择渠道 | 合格后才按顺序/优先级/负载/轮询/软粘性选择 | 备用特性约束、模型映射、冷却、并发与续接回归；多个连接共享 CLIProxy 进程，不能算独立故障域；额度独立性未知 |
| 完成调用 | 协议完成、完整交付、取消及资源释放 | 普通/流式与大 JSON 真实 HTTP；首批真实模型请求及两个编码客户端完成；不保证回答质量或用户最终任务结果 |
| 处理故障 | 明确拒绝可换源，提交不确定不重放，已开始响应不拼接 | 401/429/5xx/传输/终止事件/下游写失败回归；上游权限与额度仍是外部条件 |
| 管理权限 | 托管 Key 权限/撤销/有效期、管理会话与 CSRF 分离 | 实际后续调用及目录白名单测试；旧配置 Key 仍是全模型、无单 Key RPM/并发的明确兼容例外 |
| 控制用量 | 总并发、账号/客户端租约、RPM、请求体、队列与传输边界 | 热加载不绕过活动槽/RPM；大请求/响应与取消测试；实际额度只作上游观测，不增加商业预算系统 |
| 保护信息 | 一次性 Key、配置/URL/探测脱敏、显式导出及摘要日志 | 安全路径及导入往返实测；真实验收只留结果摘要，未保留正文或凭据 |
| 查看运行 | 独立进程存活、结构可用、近期调用事实与历史趋势 | `/livez`、`/readyz`、健康快照、持久恢复、前端统计回归；不把健康标签推广到未测组合 |
| 定位问题 | 逻辑请求关联实际发送、来源、结果和固定诊断 | 错误分类与脱敏轨迹；真实 Responses 失败保留并追到解析根因，不排除失败样本 |
| 管理变更 | 校验后原子落盘/生效，保留在途租约，配置身份隔离旧证据 | 原子事务、失败保存、重载、权限及发现冲突回归；生产未发布本轮版本 |
| 恢复服务 | 复用现有固定版本安装、回滚快照、备份验证及状态重建 | 部署/备份脚本回归与日志恢复实测；没有演练真实生产回滚或从灾难备份恢复，不称这些已通过运行验收 |

程序职责落实在上述调用、配置及观测代码。Agent 的证据分级、实际客户端验收、永久授权失效处理、增量复验和协作责任写入根目录 `AGENTS.md`；不能把 Agent 手工排障或一次测试计作后台自动能力。

## 验证与复用

完整原始结果与构建/源码摘要在 [证据目录](evidence/business-alignment-2026-10-28/validation.json)。最终整合 `go test -race -json -timeout=180s ./...` 通过 380 个测试项，完整结果见证据清单；健康索引去重、目录事实生命周期和排队取消均在最终竞态回归中复验。前端测试、所有前端 JS 语法、部署初始化/备份合约、Shell 语法、`go vet`、示例配置检查和 `git diff --check` 通过。复跑入口为 `make verify`。

实际运行使用新构建、私有临时配置/Key/日志和随机回环端口，沿现有 `Shadow` 路由访问真实上游；不切换生产服务。初轮六种 curl 组合中五项完成，Responses SSE 失败如实保留；Claude Code 进程完成。修复标准字符串 delta 后，仅重新验证受影响的 Responses SSE 与 Messages SSE，两项均完成；另以真实 Codex CLI 完成 Responses 调用。复用不受该解析修订影响的初轮普通/Chat/Claude 证据。客户端可能发起多次逻辑调用：Claude Code 的一次早期 400 与后续成功全部留在原始摘要中，不能只按客户端最终成功隐藏请求失败。

验收工具为 `tools/verify-business-runtime.py`，每次模型请求最长 45 秒、客户端进程最长 65 秒，退出保证清理子网关。使用 `--only responses_stream messages_stream` 可只补受影响范围；`--only clients --codex` 验证 Codex，`--claude` 验证 Claude Code。工具会消耗真实上游额度，仅读既有来源并在私有临时文件中启动隔离程序；不打印凭据、不保留请求/回答正文，不进行管理授权刷新。

未覆盖的外部组合仍是未知：其他别名/提供方、实际工具执行往返、实际图片输入、Embedding/Images/Rerank 上游、原生单来源增量续接及恢复后的生产调用。程序已为这些路径提供明确事实和失败边界，但没有把隔离夹具提升为真实运行证明。`source/observed_at` 的手动验证记录由管理员对具体范围负责，字段存在不自动证明其真实性。
