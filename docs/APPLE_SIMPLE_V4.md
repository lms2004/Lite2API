# Lite2API Apple Simple v4

日期：2026-08-18

## 目标

这一版不是继续优化运维细节，而是重新决定管理台的整体空间结构。

设计目标只有三条：

1. 第一眼足够简单，不像传统深色 Dashboard。
2. 页面关系直观，用户通过位置就理解“列表 → 选择 → 详情”。
3. 信息密度来自分栏、对齐和层级，而不是更多卡片、徽标和小字号。

## 核心视觉方向

采用系统界面式中性色，而不是“深蓝科技感”。

- 默认浅色：`#f5f5f7` 画布、白色内容面、黑灰文字、系统蓝操作色。
- 自动尊重系统深色模式。
- 侧栏与顶部工具栏允许轻量材质感；正文面板保持实体表面。
- 健康绿色只表达健康；普通按钮和选中状态使用蓝色或中性灰。
- 不用装饰性渐变、发光和大面积彩色卡片制造“高级感”。

## 页面结构

### 总览

`运行状态 + 四项指标` 被合并为一个主摘要容器。

下面只保留两个第一优先级区域：

- 路由健康
- 最近异常

请求记录是主要证据表；趋势图移动到页面最末并默认收起。

因此首屏从“很多仪表盘模块”变成：

```text
运行总览

┌ 当前状态 ────────────────────────────────┐
│ 健康结论                                │
│ 请求速率  成功率  P95  并发             │
└─────────────────────────────────────────┘

┌ 路由健康 ───────────────┐ ┌ 最近异常 ──┐
│                         │ │             │
└─────────────────────────┘ └─────────────┘

请求记录

运行趋势（按需展开）
```

### 路由

从“纵向堆很多路由卡片”改为 macOS 风格 Split View：

```text
┌ 模型别名 ─────┬ 当前路由详情 ───────────────────┐
│ gpt            │ gpt                             │
│ fast           │ 逻辑模型     推理强度           │
│ image          │                                 │
│                │ 1 Antigravity                   │
│ + 添加路由     │ 2 Claude Code                   │
└────────────────┴─────────────────────────────────┘
```

左侧只负责选择，右侧只编辑当前对象。这样页面不会因为路由数量增加而无限向下堆叠。

### 上游

继续使用“账号与额度 / API 与连接”两个内部视图，但视觉上改成系统分段控件和分组列表，而不是两个 Dashboard 子页面。

### 客户端

默认页首先是已创建 Key 列表。

“创建 API Key”成为页头唯一主动作。点击后才展开安全预设与高级设置；创建成功后自动收起创建区域并进入一次性明文结果和客户端配置。

## 导航和层级

- 桌面：224px 系统式侧栏。
- 中等宽度：收缩为图标侧栏。
- 手机：四项底部导航。
- 诊断工具保持次级，不与四个核心任务争夺位置。
- 顶栏仅承担当前环境、新鲜度和全局搜索，不重复页面标题说明。

## Apple 参考原则

采用的是 Apple 平台的结构逻辑，而不是模仿官网营销视觉：

- Sidebar 用于顶层导航。
- Split View 用于列表与详情同时存在的层级界面。
- 内容层级优先于装饰。
- Material 只用于帮助区分工具栏、侧栏和浮层。
- 色彩用于交互和状态，不作为背景装饰。
- 窄屏优先隐藏/折叠次级栏，而不是把所有桌面内容机械压缩。
