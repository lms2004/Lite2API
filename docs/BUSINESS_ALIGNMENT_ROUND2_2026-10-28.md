# Lite2API 第二轮业务对齐与验收

> 历史归档说明：原第二轮机器总清单未留存；2026-10-29 收尾时从仍在本机的原始输出恢复了下方链接的归档索引，明确标注未留存的源码清单和退出码。本文结果只属于其历史版本，当前实现与后续真实客户端失败见 [接续验收](CONTINUATION_ACCEPTANCE_2026-10-29.md) 和 [提交前收尾](FINAL_CLOSEOUT_2026-10-29.md)。

本轮依据原始[业务能力](BUSINESS_CAPABILITIES.md)与[八个业务用例](BUSINESS_USE_CASES.md)，继续修改 `/root/Lite2API` 的真实程序、管理台、运维脚本、测试及 Agent 指导。交付负责人为主 Agent；来源、完成契约、权限分别由限定主责整合，协议与生命周期各增加一次独立审查，修复后验证受影响路径。保留无关功能和用户原有资料，没有提交、安装或切换生产版本。

结论：本轮确认的实质偏差已经改造，当前源码的全仓竞态回归为 **500 个测试通过事件、0 失败**。实际外部来源六项精确验证、真实 Claude Code/Codex CLI 工具往返、真实 age 还原、隔离安装回退和 Docker 状态快照均有独立执行结果。这个结论限于下文的版本和范围，不把其他来源、未测特性或生产恢复描述为已验收。

## 关键执行约定

程序负责认证、权限、容量、来源筛选、安全故障处理、协议完成、配置事务与事实保存。客户端负责自身会话和工具执行。来源工具验证只运行固定无害 echo，不执行模型生成的任意命令。Agent 负责选定实际所需组合、运行验收、核对证据保存与外部依赖，并如实记录未完成条件；这些职责已同步到 `AGENTS.md`。

能力证据绑定 source identity、具体模型、接口、特性、强度、实际公开凭据及时间。共享池一个成员通过不代表整个池通过。失败保留最新检查结果与历史证明，不自动标不支持；UI 只把同范围最新 passed 描述为通过。没有增加数据库、会话注册中心、后台全面探测或任意协议转换框架。

未知可以按规则尝试；明确不支持必须排除。工具参数保证完整 JSON 对象与调用身份，不解释任意 schema，也不保证工具任务质量。提交不确定、已经开始响应与流中断不换源拼接。维护推理遵守相同总容量边界，但不污染客户端路由健康事实。

变更拒绝后有效状态保持；退出来源/撤销 Key 阻止新准入，已准入请求按原承诺结束。安装器只发布选定已提交版本，不能把当前未提交代码混入旧提交。无启用来源的首次安装只报告 bootstrap。恢复目录的 `RESTORE.json` 只证明备份时点材料还原，必须核对备份后的权限撤销和渠道变化，再完成所需调用，才能认定业务恢复。

## 最终验证

机器可读总清单、命令、原始输出、源码/产物摘要及分工交接在[第二轮证据](evidence/business-alignment-round2-2026-10-28/validation.json)。日期沿任务文件命名；每份结果保留真实 UTC 时间，部分检查已是北京时间 10 月 29 日。

- 最终 `go test -race -json ./... -count=1 -timeout=180s`：500 个通过事件（含子测试）、0 失败；`go vet`、CGO_ENABLED=0 构建与示例配置检查通过。
- `make test-web`：四个文件通过，无失败/跳过，包含控制器业务路径及生成配置的实际解释；全部前端 JS 语法通过。
- `make test-deploy`：现有 bootstrap/模拟 age 合约、Shell 语法及六项独立生命周期回归通过。模拟 age 仅证明其检查契约和取消清理。
- 真实 age 且显式启用 Docker 的 `make test-lifecycle`：还原八项通过、升级四个分支通过、实际 Compose 快照一项通过，无跳过。还原套件 18.610 秒、升级 13.35 秒、快照 6.489 秒是本机夹具执行时长，不能当作生产 RTO。
- 真实来源：同一具体 antigravity 模型与实际公开凭据上，Chat/Responses/Messages 的完整文本流和非流工具往返六项通过，六份精确事实已保存并读回。真实 Claude/Codex 工具调用均完成；后续只改动观测细分、维护准入和管理台配置产物，复用上述未改变的协议/工具证据。最终静态构建再补一项真实 Responses 完整流，HTTP 200、逻辑 success、一次发送。
- 生产只读核对仍为原 MainPID 209943、active/running；自行创建的 Docker 测试资源无残留。测试没有安装生产版本或覆盖生产状态。

## 失败记录与增量复用

用户固定副本 2026-10-28 23:06:28 的 340 个通过事件及一项缺模型回退失败继续原样保存在历史证据中，不改写成通过。当前对应 fixture 改为真正的 Embeddings 响应；它在本轮最终回归通过，只证明当前隔离回退路径。

本轮初次集成发现重复字段防护破坏大字段数请求的零分配拒绝要求；改为先有界记录字段跨度、拒绝超限再解码检查，原失败日志和修复后结果均保留。一次独立协议审查和一次生命周期审查发现的契约/清单/落盘缺陷也已修复，并保留修复前输出。

真实验收首次六项来源检查返回 401，根因是验收工具继承的默认环境变量覆盖私有管理 Token，并非已确认上游不支持；修复验收隔离后只重跑受影响的六项检查，全部通过。首次真实工具客户端已经完成，因此不重复消耗额度。Claude 初次一项逻辑请求为上游 400，随后请求完成；原始摘要完整保留，不能把客户端最终完成解释为全部逻辑请求成功。

## 仍然保留的边界

1. 未测的来源/别名/池内凭据、图像理解、Embedding/Images/Rerank 真实上游、任意工具 schema、原生 thinking、原生单来源增量续接仍没有实际供应商验收。独立文本流与非流工具验证不能推定流式工具组合；真实客户端工具往返只证明本次具体客户端路径。
2. 生命周期使用真实加解密、Go、HTTP、chroot 和 Docker；上游授权/模型为受控夹具，systemctl 为只管理私有进程的替身。没有验证真实 systemd sandbox、生产完整拓扑灾备、外部介质可得性或真实 OAuth 平台重新授权。
3. CLIProxy 安装器增加指定受影响来源的业务门禁，但本轮没有执行其真实安装/升级。固定版本与补丁检查仍是外置适配器运维职责。生产升级、维护窗口和生产恢复验收没有执行。
4. 备份不能凭空恢复备份后变化，旧授权文件不能恢复外部撤销的 grant。灾难恢复最终仍需外部资格、依赖和实际客户端验收。跨文件捕获检测到变化就拒绝发布；容器外写入者应先停写。
5. 未运行浏览器视觉/无障碍验收；本轮管理台证据为控制器、真实配置产物解析及嵌入资源测试，不宣称 UI 视觉通过。金额预算、计费、多租户、多节点一致性与模型回答质量保持目标范围之外。
